# 株の売買判断ツール

yfinance から取得した株価データをもとに、テクニカル指標(移動平均クロス・RSI・MACD・ボリンジャーバンド)を
組み合わせて「買い / 売り / 様子見」を機械的に判定するWebアプリです。

**投資助言ではありません。** 表示される判断はあくまで参考情報であり、最終的な投資判断はご自身の責任で行ってください。

## 構成

- `backend/` — FastAPI アプリケーション
  - `main.py` — APIエンドポイントとフロントエンドの配信
  - `indicators.py` — SMA/RSI/MACD/ボリンジャーバンドの計算
  - `judge.py` — 指標を組み合わせた売買判断ロジック
  - `patterns.py` — チャートパターン(ダブルトップ/ボトム・三尊/逆三尊・三角保ち合い)の検出ロジック
  - `pattern_api.py` — 複数銘柄をスキャンするパターン検出API
  - `pattern_backtest.py` — パターンの的中率検証(バックテスト)と確率モデルの学習
  - `market_data.py` — 株価データの取得(yfinance / CSV)
  - `universes.py` — スキャン対象のプリセット銘柄リスト
- `data/pattern_stats.json` — 過去データでのパターン別の実績(画面の「過去の実績」「過去データでの検証」に表示)
- `data/pattern_model.json` — 完成確率・目標到達確率を推定するモデル
- `frontend/index.html` — 銘柄コードを入力してチャートと判断結果を表示する画面(Chart.js使用)
- `frontend/patterns.html` — パターンが発生しそうな銘柄を一覧表示するスクリーナー画面
- `tests/` — パターン検出のテスト(`python -m pytest tests`)

## セットアップ

```bash
pip install -r requirements.txt
```

## 起動

```bash
uvicorn backend.main:app --reload
```

ブラウザで `http://localhost:8000` にアクセスすると画面が表示されます。

## 使い方

1. 銘柄コードを入力します。
   - 日本株: `7203.T` (トヨタ自動車) のように証券コード + `.T` を指定
   - 米国株: `AAPL` のようにティッカーをそのまま指定
2. 取得期間を選択します。
3. 「判断する」を押すと、直近データを取得し以下を表示します。
   - 総合判定(買い / 売り / 様子見)とスコア
   - 各指標(移動平均クロス・RSI・MACD・ボリンジャーバンド)ごとの判定根拠
   - 株価チャート(移動平均線・ボリンジャーバンド付き)

## 判断ロジックの概要

各指標にスコアを付け、合計スコアでトレンドの強さを判定します。

| 指標 | 買いシグナル | 売りシグナル |
| --- | --- | --- |
| 移動平均クロス(25日/75日) | ゴールデンクロス(+2) / 短期線が上(+1) | デッドクロス(-2) / 短期線が下(-1) |
| RSI(14) | 30未満(売られすぎ, +1) | 70超(買われすぎ, -1) |
| MACD | シグナル上抜け(+2) / MACDがシグナルの上(+1) | シグナル下抜け(-2) / MACDがシグナルの下(-1) |
| ボリンジャーバンド | 株価が下限バンド以下(+1) | 株価が上限バンド以上(-1) |

合計スコアが `+2` 以上で「買い」、`-2` 以下で「売り」、それ以外は「様子見」と判定します。
しきい値は `backend/judge.py` の `BUY_THRESHOLD` / `SELL_THRESHOLD` で調整できます。

## API

```
GET /api/analyze?ticker=7203.T&period=6mo
```

- `ticker`: 銘柄コード(必須)
- `period`: `1mo` / `3mo` / `6mo` / `1y` / `2y` / `5y`(デフォルト `6mo`)

レスポンスにはOHLCV由来の指標履歴・総合判定・判定根拠が含まれます。

## チャートパターン検出(スクリーナー)

`http://localhost:8000/patterns.html` を開き、対象銘柄(日本株主要40銘柄 / 米国株主要30銘柄 / 任意の銘柄コード)を選んで
「スキャン」を押すと、以下のパターンが **形成中または完成直後** の銘柄を一覧表示します。
行をクリックすると、パターンを構成する山・谷とネックライン(三角形は上下の線)・目標値をチャート上に表示します。

| パターン | 示唆 | 出力される進行段階 |
| --- | --- | --- |
| ダブルトップ / ダブルボトム | 下落 / 上昇 | 2つ目の山(谷)を形成中 / ネックラインへ接近中 / ブレイク直後 |
| 三尊 / 逆三尊 | 下落 / 上昇 | 右肩を形成中 / ネックラインへ接近中 / ブレイク直後 |
| 上昇三角形 / 下降三角形 | 上昇 / 下落 | 三角形が収束中 / ブレイク直後 |
| 対称三角形 | ブレイク方向次第 | 三角形が収束中(方向待ち) / ブレイク直後 |

各候補には次の値を表示します。

- **完成確率**: ブレイク前のパターンが、崩れる(否定ラインを超える)前にネックラインを抜ける確率(40営業日以内)
- **目標到達確率**: 否定ラインより先に目標値へ到達する確率(60営業日以内)。一覧はこの順に並びます
- **過去の実績**: 同じパターン・進行段階が過去に何件あり、20営業日後に市場平均と比べてどうだったか

### 判定の仕組み

1. 過去1年の日足の高値・安値から、ZigZag で山と谷を抽出します。反転とみなす幅は銘柄の ATR(値動きの大きさ)の2.5倍(3〜15%)で、画面の「感度」で調整できます。
2. 直近の山・谷の並びが各パターンの条件(山の高さの差3%以内、三尊の頭が両肩より高い、三角形は山・谷に引いた線が収束している 等)を満たすか判定します。底型と下降三角形は、価格を上下反転して天井型・上昇三角形と同じロジックで判定します。
3. 現在値とネックラインの位置から進行段階を決めます。ブレイクから5営業日を過ぎたもの・目標値に到達済みのものは「発生済み」として除外します。
4. 確率は、過去データで学習したロジスティック回帰モデル(`data/pattern_model.json`)で推定します。入力はパターン×進行段階、ネックラインまでの進み具合、山の揃い具合、パターンの大きさ、直前トレンド、出来高の変化です。

しきい値は `backend/patterns.py` の `Params` で調整できます。

## パターンの的中率検証(バックテスト)

`backend/pattern_backtest.py` は、過去の各営業日に「その日までのデータだけ」でスクリーナーと同じ判定を行い
(画面の判定と結果が一致することをテストで確認しています)、パターンが新たに検出された翌日の始値から、その後どう動いたかを測ります。

```bash
# 日本株の主要銘柄(yfinance で10年分を取得)で検証し、統計とモデルを作り直す
python -m backend.pattern_backtest --universe jp_major --period 10y

# 任意の銘柄 / 縦持ちCSV(date, open, high, low, close, volume, Name)でも検証できます
python -m backend.pattern_backtest --tickers 7203,6758,9984 --period max
python -m backend.pattern_backtest --csv prices.csv --split-date 2016-01-01
```

出力は `data/pattern_stats.json`(画面の「過去の実績」「過去データでの検証」)と `data/pattern_model.json`(確率モデル)です。
モデルは `--split-date` より前で学習して以降で予測精度を確かめたうえで、全期間で学習し直して保存します。

### 同梱の検証結果(米国S&P500採用銘柄、2013〜2018年)

開発環境から日本株のデータを取得できなかったため、同梱の統計・モデルは公開データセット
([plotly/datasets の all_stocks_5yr.csv](https://github.com/plotly/datasets)、488銘柄・約5万件の検出)で作成しています。
日本株で使う場合は、上記コマンドで作り直すことをおすすめします。

- **パターンが完成するか・目標値に届くかは、ある程度予測できます。** 2015年までで学習し2016年以降で予測したところ、
  AUC は完成確率 0.67・目標到達確率 0.67 で、予測した確率と実際の割合もほぼ一致しました(例: 予測27.5% → 実際26.9%、予測70.1% → 実際72.7%)。
  元の手作りスコアの AUC は 0.58〜0.59 でした。ネックラインに近いほど完成しやすく、パターンが大きいほど(目標が遠いため)到達しにくい傾向です。
- **一方で、パターンに従って売買しても市場平均には勝てていません。** 20営業日後の騰落率を同じ日の全銘柄平均と比べると、
  どのパターン・段階も ±0.6% 以内でした。前半(〜2015年)と後半(2016年〜)で符号が揃っていたのは18区分中8つで、
  偶然でも同程度は揃うため、安定した優位性とは言えません(例外的に目立つのは逆三尊の右肩形成中: +0.31% / +0.64%)。
  下落示唆のパターンの「勝率」が4割前後なのは、この期間に相場全体が上昇していたためです。
- パラメータ(ZigZag の幅 2.0/2.5/3.0×ATR、山の高さの許容差 2/3/5%)を変えても、市場平均との差はいずれも ±0.04% 以内で、
  検出数と予測しやすさのトレードオフが変わるだけだったため、既定値は変えていません。

つまり、このツールは「どの銘柄でパターンが形成されつつあり、それが完成しそうか」を絞り込むのには使えますが、
パターンが出たことだけを理由に売買しても有利になるとは言えません。

### API

```
GET /api/patterns/scan?universe=jp_major&min_score=30
GET /api/patterns/scan?universe=custom&tickers=7203,6758,AAPL
GET /api/patterns/detail/7203.T
GET /api/patterns/stats
GET /api/patterns/universes
```

- `patterns`: `double_top,double_bottom,head_and_shoulders,inverse_head_and_shoulders,ascending_triangle,descending_triangle,symmetric_triangle` から絞り込み(省略で全て)
- `stages`: `second_peak,right_shoulder,approaching,converging,breakout` から絞り込み(省略で全て)
- `min_score`: 目標到達確率(%)の下限。方向未定の対称三角形(収束中)は確率がないため、指定すると除外されます
- `sensitivity`: 0.5〜2.0(大きいほど小さな波も検出)。確率モデルは標準(1.0)で学習しています
- 4桁の証券コードには自動で `.T` を付与します。株価データは30分間キャッシュします。
